# KATFIT BALANCE: инструкция для менеджеров по работе в CRM

Кратко: это пошаговая инструкция, куда нажимать и что заполнять в Twenty CRM. Технические детали — в [техспеке](katfit-balance-crm-technical-spec.ru.md) и [плане развития](katfit-balance-crm-development-plan.ru.md).

## 1. Зачем эта CRM

Twenty — рабочее место менеджера студии: лиды с сайта, ответы, запись на первое занятие, продажи, пакеты, явка и повторные покупки.

В CRM **нужно** вести:

- кого и когда пригласили;
- кто записан на intro и пришёл ли;
- кто купил пакет и сколько занятий осталось;
- следующий шаг по каждому активному человеку.

В CRM **не нужно** вести:

- кассу и чеки как фискальный учёт (касса остаётся источником правды по платежу);
- диагнозы и медицинские комментарии;
- технические задачи разработки;
- базу марафона и другие продукты экосистемы.

Заявка с лендинга — это интерес, а не запись, бронь или оплата.

## 2. Как открыть и ориентироваться

1. Откройте адрес workspace Twenty (ссылку выдаёт администратор).
2. Войдите под своей рабочей учётной записью.
3. Слева — меню разделов. Основные для ежедневной работы:

| Раздел в меню | Что там |
| --- | --- |
| Люди / People | Карточки клиентов и лидов |
| Сделки / Opportunities | Путь человека до первой покупки |
| Задачи / Tasks | Что сделать сегодня и просроченное |
| Заметки / Notes | Итоги звонков и договорённости |
| Записи / Bookings | Кто записан на занятия |
| Занятия / Class Sessions | Конкретные слоты по дате и времени |
| Группы / Class Groups | Постоянные группы |
| Пакеты / Memberships | Купленные пакеты клиентов |
| Оплаты / Payments | Реестр оплат (управленческий) |
| Продукты / Products | Прайс (обычно только смотреть) |

Если пункта ещё нет в меню — напишите администратору: объект мог быть не включён в текущую версию workspace.

### Как читать списки

- Вверху списка — **представления (views)**: готовые фильтры («Новые лиды», «Intro без покупки» и т.д.).
- Переключайте представление вкладками над таблицей, не собирайте фильтр каждый раз заново.
- Открыть карточку: клик по строке.
- Создать запись: кнопка **New** / **Создать** в правом верхнем углу списка.
- Поиск: поле поиска вверху — по имени, телефону, email.

### Карточка записи

В карточке:

- слева или сверху — основные поля;
- справа / снизу — связанные объекты (задачи, заметки, записи, пакеты);
- вверху — действия (если настроены): записать, отметить явку, подтвердить оплату.

Сохраняйте изменения явно, если интерфейс показывает кнопку **Save**. Многие поля сохраняются сразу после выхода из ячейки.

## 3. Главные понятия простыми словами

| В интерфейсе | Смысл |
| --- | --- |
| **Человек (Person)** | Один клиент на весь путь: от заявки до постоянного посетителя |
| **Сделка (Opportunity)** | Только путь **до первой покупки**. Продление пакета — не новая сделка |
| **Статус клиента** | Где человек в жизненном цикле студии |
| **Стадия сделки** | Где человек в воронке до первой оплаты |
| **Задача** | Конкретное действие с датой: позвонить, написать, предложить слот |
| **Заметка** | Что сказали / договорились — без медсведений |
| **Запись (Booking)** | Место человека на конкретном занятии |
| **Занятие (Class Session)** | Один слот: дата, время, формат, тренер |
| **Группа (Class Group)** | Постоянная группа по дню/времени |
| **Пакет (Membership)** | Купленный продукт с остатком посещений и сроком |
| **Оплата (Payment)** | Факт оплаты для учёта в CRM (чек — отдельно в кассе) |

`Companies` (компании) для обычных клиентов **не используем**. Туда попадают только поставщики, партнёры, арендодатель.

## 4. Статусы: когда что ставить

### 4.1. Статус клиента (поле «Статус клиента»)

| Статус | Когда ставить |
| --- | --- |
| Лист ожидания | Заявка до открытия / пока запись недоступна |
| Лид | Можно приглашать и записывать, покупки ещё нет |
| Связались | Был содержательный контакт |
| Записан на intro | Есть будущая intro-запись |
| Посетил intro | Intro состоялось, пакет ещё не куплен |
| Активный клиент | Есть активный пакет или оплаченная будущая запись |
| Пауза | Клиент временно не ходит, пауза подтверждена |
| Ушёл | Нет активности, уход подтверждён — укажите причину |
| Возврат | Запущена попытка вернуть ушедшего |

### 4.2. Стадии сделки (воронка первой покупки)

| Стадия | Что уже произошло | Что делать дальше |
| --- | --- | --- |
| Лист ожидания | Заявка получена | Держать в списке до приглашения |
| Новый лид | Можно звонить / писать | Связаться в срок SLA |
| Связались | Контакт состоялся | Предложить intro |
| Предложено intro | Слоты предложены | Дождаться выбора и записать |
| Intro записано | Есть бронь | Напомнить и дождаться явки |
| Intro посещено | Человек пришёл | Предложить пакет и закрыть покупку |
| Первая покупка | Оплата подтверждена | Сделка закрыта успешно |
| Потерян | Не купил / отказался | Указать причину, сделку больше не двигать |

Стадию двигайте **только после факта**, а не «на всякий случай вперёд».

## 5. С чего начать рабочий день

Каждое утро пройдите списки по порядку:

1. **Задачи** → ваши на сегодня и просроченные. Закройте или перенесите с новой датой.
2. **Новые лиды** (представление сделок) → ответьте всем без первого контакта.
3. **Нарушение SLA** → приоритет: кто ждёт дольше всех.
4. **Ближайшие записи** → проверьте intro и занятия на сегодня/завтра.
5. **Требуется отметить явку** → закройте вчерашние занятия.
6. **Intro без покупки** → follow-up тем, кто уже был на первом занятии.
7. **Пакеты заканчиваются** → предложите продление.

Правило качества: у каждого активного лида есть **ответственный**, **следующее действие** и **дата**.

## 6. Сценарии: куда нажимать

### 6.1. Пришла заявка с сайта

Обычно Person и Opportunity создаются автоматически. Вам приходит задача и/или уведомление.

**Что сделать:**

1. Откройте **Задачи** или представление **Новые лиды**.
2. Откройте сделку → перейдите к связанному **человеку**.
3. Проверьте: имя, телефон/email, удобное время, формат, согласие на ПДн.
4. **Не создавайте второго человека**, если контакт уже есть. Сначала поиск по телефону, потом по email.
5. Если дубль очевиден (тот же телефон) — работайте в существующей карточке и сообщите администратору. Не склеивайте сами спорные случаи (телефон одного человека + email другого).

Если заявку нужно завести **вручную** (звонок, walk-in, личное сообщение):

1. **Люди → New**.
2. Заполните имя, телефон и/или email.
3. Статус клиента: `Лид` (или `Лист ожидания`, если запись ещё недоступна).
4. Канал связи, интересующий формат, удобное время — если известны.
5. Источник: `WALK_IN`, `DIRECT_MESSAGE`, `REFERRAL` и т.п. First-touch после заполнения не меняйте сами.
6. Согласие на ПДн — только если человек подтвердил его.
7. Создайте **сделку**: название вида `Имя — первое занятие`, стадия `Новый лид`, свяжите с человеком, назначьте себя ответственным.
8. Создайте **задачу** «Связаться» с датой на сегодня/завтра.

### 6.2. Первый ответ лиду

1. Откройте карточку человека или сделки.
2. Позвоните / напишите в предпочитаемый канал.
3. В **Notes** кратко зафиксируйте итог: дозвонились / не ответил / интерес / возражение. Без диагнозов.
4. Создайте или обновите **задачу** на следующий шаг с датой.
5. В сделке переведите стадию в **Связались** (если контакт был содержательным).
6. В человеке обновите **Статус клиента** → `Связались` и поле **Следующее действие**.

Если не дозвонились: оставьте стадию `Новый лид`, поставьте задачу на повторный контакт, в заметке укажите попытку.

### 6.3. Предложить и записать на intro

1. В сделке стадия → **Предложено intro**.
2. Согласуйте слот.
3. Откройте нужное **занятие** (Class Session) или создайте intro-слот по регламенту администратора.
4. Действие **Записать** / создайте **Booking**:
   - клиент = этот человек;
   - тип = Intro;
   - статус = Booked.
5. Привяжите запись к сделке в поле **Intro-запись**, если поле есть.
6. Стадия сделки → **Intro записано**.
7. Статус клиента → `Записан на intro`.
8. Задача: напоминание за сутки и/или за 13–14 часов до границы отмены (12 часов).

Не записывайте человека «поверх» заполненной группы без свободного места.

### 6.4. Отметить явку после занятия

1. Откройте **Занятия** → представление **Требуется отметить явку** (или само занятие).
2. Для каждой записи выберите исход:
   - **Посетил** (Attended);
   - **Не пришёл** (No-show).
3. Сохраните / выполните действие **Отметить явку**.
4. Для intro:
   - пришёл → стадия **Intro посещено**, статус клиента `Посетил intro`;
   - создайте задачу «Предложить пакет» на тот же или следующий день.
5. Поздняя отмена и no-show списывают занятие по правилам студии — не «прощайте» вручную без решения владельца.

### 6.5. Продать первое занятие / пакет

1. Убедитесь, что оплата прошла и чек выбит в кассе (наличные или СБП).
2. В CRM: **Оплаты → New** (или действие **Подтвердить оплату** на карточке):
   - клиент;
   - продукт (Первое занятие / Пакет 4 / Пакет 8 / Разовое / Персональное);
   - сумма;
   - метод: Cash или SBP;
   - статус: Paid;
   - идентификатор/ссылка на чек, когда есть.
3. Создаётся **Membership** (пакет) — проверьте остаток посещений и срок.
4. Для первой покупки:
   - стадия сделки → **Первая покупка**;
   - статус клиента → `Активный клиент`.
5. Сразу помогите записаться на ближайшие занятия из пакета.

Цены и состав продуктов не меняйте в карточке продукта. Если нужна другая цена — это решение владельца / новая версия тарифа.

Актуальный ориентир (утверждённые и рекомендованные):

| Продукт | Цена | Комментарий |
| --- | ---: | --- |
| Первое групповое на реформере | 1 500 ₽ | Утверждено |
| Разовое групповое | 2 500 ₽ | Утверждено |
| Пакет 4 | 8 800 ₽ | До утверждения — уточняйте у владельца |
| Пакет 8 | 16 000 ₽ | До утверждения — уточняйте у владельца |
| Персональное | 4 000 ₽ | Утверждено |

### 6.6. Клиент не купил / отказался

1. Стадия сделки → **Потерян**.
2. Обязательно заполните **причину потери**.
3. При необходимости — статус клиента `Ушёл` и та же причина.
4. Если уместен возврат позже — задача на дату follow-up или статус `Возврат` по решению менеджера/владельца.

### 6.7. Отмена записи клиентом

1. Откройте **Booking**.
2. Действие **Отменить** / смените статус по правилу:
   - отмена **≥ 12 часов** до начала → своевременная; при лимите месяца может появиться право на отработку;
   - отмена **< 12 часов** → поздняя, занятие списывается;
   - **no-show** → списание.
3. Зафиксируйте время отмены (система должна считать часы сама; не подгоняйте статус «на глаз»).
4. Предложите новый слот, если отмена своевременная и есть отработка/остаток.

Отмена **студией** — отдельное действие на занятии, не через клиентскую отмену. Клиентский лимит отработок при этом не тратится.

### 6.8. Повторная продажа и удержание

1. Откройте представление **Пакеты заканчиваются**.
2. Откройте человека → вкладка пакетов.
3. Свяжитесь, предложите продление.
4. После оплаты — новая оплата и новый Membership (не новая Opportunity первой покупки).
5. Клиентов без будущей записи и без визита 14/30 дней ведите по соответствующим спискам, не ждите, пока «сами вспомнят».

### 6.9. Пауза и уход

- **Пауза**: статус `Пауза`, заметка с договорённостью, дата следующего контакта, задача.
- **Уход**: статус `Ушёл` + причина. Не удаляйте карточку.

- [ ] Имя
- [ ] Телефон и/или email
- [ ] Статус клиента
- [ ] Ответственный
- [ ] Следующее действие (для активных лидов)
- [ ] Согласие на ПДн (для заявок с сайта — уже должно быть)
- [ ] Причина — если статус «Ушёл»

### Сделка до первой покупки

- [ ] Связанный человек
- [ ] Стадия
- [ ] Ответственный
- [ ] Источник (если известен)
- [ ] Intro-запись — когда записали
- [ ] Причина потери — если «Потерян»

### После каждого контакта

- [ ] Заметка с итогом
- [ ] Задача на следующий шаг с датой
- [ ] Стадия и статус соответствуют факту

## 8. Что нельзя делать

- Создавать дубль человека «чтобы быстрее».
- Менять first-touch источник и UTM после первого заполнения.
- Двигать стадию вперёд без факта (например, «Intro посещено», если человек не пришёл).
- Писать в заметках диагнозы, ЛФК, «болит спина» как медкарту.
- Править остаток пакета вручную без причины и согласования.
- Удалять сделки и оплаты «для красоты списка».
- Считать заявку waitlist записью или оплатой.
- Вести продажи мимо CRM «в голове» или только в мессенджере.

## 9. Типичные ошибки и что делать

| Ситуация | Действие |
| --- | --- |
| Два человека с одним телефоном | Работайте в одной карточке, вторую не наполняйте; эскалируйте админу |
| Телефон указывает на А, email на Б | Не объединяйте; задача администратору |
| Повторная заявка с сайта | Не создавайте новую сделку, если открытая уже есть; обновится last-touch |
| Забыли отметить явку | Закройте через «Требуется отметить явку» в тот же день |
| Оплата есть, в CRM нет | Внесите Payment + Membership в день оплаты |
| Клиент просит перенести «без списания» при поздней отмене | Объясните правило 12 часов; исключение — только решение владельца |

## 10. Роли: что обычно может менеджер

Менеджер / тренер-оператор обычно может:

- создавать и обновлять людей, сделки, задачи, заметки;
- работать с записями и явкой через предусмотренные действия;
- подтверждать оплаты в рамках правил;
- смотреть продукты и активные пакеты.

Обычно **не** делает сам:

- менять модель данных и роли;
- править прайс «на лету»;
- массово удалять и импортировать данные;
- склеивать спорные дубли без администратора.

Точные права зависят от роли в workspace. Если кнопки нет — это ограничение доступа, а не «сломанный» экран.

## 11. Если чего-то нет в интерфейсе

Часть сценариев (автозаведение с лендинга, кнопки «Записать» / «Отметить явку», автосоздание пакета) включается по мере внедрения. Пока действия нет:

1. Ведите человека, сделку, задачи и заметки вручную по этой инструкции.
2. Статусы и стадии обновляйте сами по факту.
3. Записи и оплаты заводите как обычные записи объектов, если разделы уже доступны.
4. Сообщите администратору, какого действия не хватает.

Не придумывайте параллельную таблицу в Excel для тех же лидов — иначе появятся два источника правды.

## 12. Мини-шпаргалка на день

```text
Утро: задачи → новые лиды → SLA → записи на сегодня
День: ответы, intro, продажи, правки броней
Вечер: явка по прошедшим занятиям → follow-up intro без покупки → пакеты к концу
Всегда: заметка + следующий шаг с датой
```
