## Дефекты

### P1 — UI сохраняет недопустимую сумму и делает месячные отчёты недоступными

Шаги: открыть тестовый расход → Сумма → `0` → Enter; повторить с `-1,25`. Ожидается отклонение с понятной ошибкой и сохранением прежнего значения. Фактически оба значения сохранены (REST: 0 и -1250000 микрорублей), UI ошибки не показывает. POST report за октябрь и ноябрь возвращает HTTP 409 с UUID. Это результат прямой правки CRM через штатный UI, а не проверка валидации маршрута save. Скриншоты: [нулевая сумма](02-zero.png), [отрицательная сумма](03-negative.png). [Ответы API](report-errors.txt).

### P1 — «Месяц начисления» позволяет сохранить не первое число

Шаги: открыть расход с корректной суммой → Месяц начисления → выбрать 15 октября 2026. Ожидается выбор месяца с нормализацией до 2026-10-01 либо отказ. Фактически сохранено 2026-10-15, оба месячных отчёта отвечают 409. [Скриншот](04-wrong-accrual-day.png), [ответы API](report-errors.txt). После фиксации даты через UI восстановлено 2026-10-01; отчёты снова 200.

### P2 — создание пустой записи без обязательных полей и без отмены

Шаги: Расходы → Создать новый Расход → Escape → закрыть боковую панель → reload. Ожидается возможность отменить создание без записи и проверка обязательных полей перед сохранением. Фактически новая пустая запись уже существует, totalCount увеличивается. [Скриншот](06-cancel-retained.png), [независимое чтение](cancel-api.txt). Пустая запись без дат не попала в отчёты октября/ноября. После проверки она явно помечена и заполнена как неоплаченный расход, без удаления.

### P2 — сокращённая сумма скрывает копейки

Шаги: сохранить 1234,56 / 1500,25 / 10,01 ₽ и закрыть редактор поля. Ожидается возможность увидеть точную сумму расхода в реестре и карточке. Фактически видны 1.2k / 1.5k / 10; точные значения доступны только после открытия редактора. [Созданная запись](01-created.png), [точная сумма в редакторе](09-final-exact-amount.png). Данные в CRM при этом точны.

### P3 — несуществующая дата молча игнорируется

Шаги: Дата выплаты → ввести `31/11/2026` → Enter. Ожидается сообщение о неправильной дате. Фактически редактор закрывается, остаётся 2 ноября, сообщения нет. REST подтверждает сохранность прежнего значения. [Скриншот](05-invalid-date.png). Сетевой сбой не установлен; трафик UI-запроса не записывался.
